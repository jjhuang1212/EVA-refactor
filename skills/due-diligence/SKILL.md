# 公司尽调

尽调 = 把一家公司的工商登记、股权、人员、司法与处罚几个侧面各查一遍，写成一份带出处的报告。每个维度都是付费查询，先定范围再动手。**这个场景默认出报告**，有实质内容就按 `report` skill 出 PDF（用户要别的格式听用户的）。

## 先定范围

1. 用 `resolve_entity` 把公司对齐到信用代码。对不上的，按系统提示里的办法告诉用户，不继续。起点公司是境外主体（没有信用代码，`query_company` 的各维度都查不了）时，先 `load_skill web-research`，用 `web_search` 查它的注册地、业务、股东和实际控制人、人员、涉诉与处罚、近期新闻，出简版报告：全部内容放进"公开网页信息"一节，每条带 `【w编号「摘抄」】`；开头和数据缺口里写明"无企业数据库记录，以下均为网页来源，未核验"。生成报告时 `r.scenario("due-diligence", "", gaps)` 的信用代码传空字符串，`gaps` 把每个维度都写上"境外主体，无企业数据库记录"。
2. 用户上传了材料（年报、合同、访谈稿），先 `read_file` 读完。文件里的说法和工商登记信息不一致时，两边都写，不替用户裁决。
3. 默认查下面"章节与维度"里的全部维度。开查前告诉用户要查哪几项；用户说"只看风险""不用查股权"就按用户的缩。股权往下穿透不是默认动作，用户要才做，做法见 `equity-penetration`。
4. 对 `query_company` 报错的维度不要对同样参数重试；记下"该项暂时取不到"，继续别的，最后如实写进数据缺口。

## 章节与维度

| 章节 | 维度（`query_company` 的 dimension） | 写什么 |
|---|---|---|
| 主体概况 | `registration`、`key_personnel` | 法定代表人、登记状态、成立日期、注册资本、实缴资本、企业类型、注册地址、经营范围、主要人员 |
| 股权与实际控制人 | `shareholders`、`actual_controller` | 直接股东和比例、实际控制人。比例的算法和"总持股比例不等于间接持股"的区别见 `equity-penetration` |
| 对外投资与关联 | `investments` | 被投资企业和持股比例；名单只有名字，没对齐的标"未对齐" |
| 司法与执行 | `dishonest`、`judgment_debtor`、`judicial_documents`、`court_notice`、`case_filing` | 失信、被执行、裁判文书、法院公告、立案。有记录写案号、案由、金额、日期 |
| 行政处罚 | `administrative_penalty` | 决定书文号、处罚结果、金额、单位、日期 |
| 数据缺口与口径 | （不查，汇总前面的） | 见下 |

招投标（`bidding`）不在默认范围，用户问业务往来、中标情况时才查。

## 表格和名单怎么写，才不误导

- `query_company` 返回的名单可能不全（"只展示了前 N 条，共 M 条"，这是接口的限制）。报告里要分清两件事：接口返回了多少、报告里列了多少。
  写成"接口返回了前 100 家（共 164 家），本报告列出其中 13 家（按持股比例从高到低挑选）"。列了几条就写几条，不要写"以下列出前 100 家"却只列几家。
  要么把返回的全部列出来（长名单放在章节末尾的表里），要么写明是挑选的。
- 表格里某一列的值，只能来自这条记录自己的字段。`key_personnel` 的记录多数没有持股字段：写"该维度未提供"，不要写"—"或"无"，那会被读成"没有持股"。
  这个人如果出现在股东名单或是实际控制人，那一格写"见股权与实际控制人一章"，不要留空。
- `actual_controller` 的"总持股比例"是控制链合计，不等于这个人通过某家公司间接持有的比例。没有往下穿透过，就不要写"通过某某公司间接持有 X%"，
  只写"实际控制人为某某，总持股比例 X%（企业数据口径）"，并在数据缺口里写明"未穿透，间接持股比例未核算"。

- 数据里没写的性质判断不要写：例如"某某公司是实际控制人的持股平台""某机构是代持机构"，数据只给了名称和比例。确实要写，标明"推测"并说明依据是哪几条数据，不要放进没有引用的陈述里。

## 写"没有"要小心

- `query_company` 返回「没有记录」时，报告里写"截至取数时间（写明日期），未查到该项记录"。这是查询结果，不是对公司的结论：不要写成"无风险""经营良好""合规"。
- 查失败、查不到、没对齐，和"查了没有"是三回事，数据缺口一章里分开列：
  - 没有记录：哪几项、取数时间。
  - 暂时取不到：哪几项，原因（报错码）。
  - 没查：哪几项、为什么（用户缩小范围、历史类信息当前不可用）。
- 历史类信息（历史股东、历史高管、历史处罚）当前查不了，数据缺口里写明"不含历史信息"。
- 返回写明"只展示了前 N 条，共 M 条"时，报告里照写，说明名单或案件不全，不要当成全部。

## 交付前会核对维度覆盖

生成报告时用 `r.scenario("due-diligence", 信用代码, gaps)` 声明场景和公司。`deliver_file` 前会按上面表里的维度逐项核对，不通过就不交付，并告诉你缺哪几项：

- 查到记录的维度，报告里要至少引用一条它的 `q` 编号。
- 查了、确认没有记录的维度，放行。
- 没查、没匹配上、查失败的维度，要补查，或在 `gaps` 里写明原因，例如 `{"shareholders": "用户要求不查股权", "case_filing": "接口报错，暂时取不到"}`。同样的话也要写进"数据缺口与口径"一章，`gaps` 只是让交付检查知道你是有意没查。

## 出处和日期

- 每个来自企业数据的事实写 `【q编号「摘抄原文」】`，来自文件的写文件引用。自己算的数写明据哪几条算的。
- "没有记录"这类陈述没有 q 编号可引，不要为了凑引用编一个。
- 封面信息里放"数据取数时间"：取各维度返回里最早的和最晚的；同一维度可能是几天前的缓存，返回里写明了。
- 风险类数据变化快，报告里提醒"以取数时间为准，需要最新状态请重新核查"。

## 联网补充

联网搜索只作补充（新闻、公告；境外主体见上），搜之前先 `load_skill web-research`，单独成一节"公开网页信息"，每条带 `【w编号「摘抄」】` 并按 `report` 的要求登记来源。网页与文件、工商登记信息不一致时以后两者为准，在报告里写明两边各是什么。聚合站转载的内容出处层级低，用到要写明是网页来源。

## 交付前自查

- 每章的数字、日期和你查到的逐条对得上；没有一句"无风险"这类结论性说法。
- 数据缺口一章把"没有记录""取不到""没查"分开了。
- 引用格式对、摘抄是原文（交付前会被逐条核对，不通过会被拒绝）。
