# 出报告

## 先判断要不要出

出报告的情况（满足任意一条）：
1. 当前场景的 skill 写明"默认出报告"，并且这次确实有实质内容。
2. 用户明确要求（"出个报告""生成 PDF""要 Word 版"）。格式听用户的；没说就出 PDF。

不出报告的情况，直接用文字回答，并说明为什么没有出：
- 没有新发现，或关键材料读不到、查不到，凑出来的报告只会是空话。
- 用户只是问一个问题、闲聊、或者要的是一个数字。
- 内容短到几句话能说清。

"最终报告"指一个任务或场景的最终成果，它出 PDF（用户要求其他格式时听用户的）。中间过程的文字回答再长，也直接写在回答里，不用你做成文件，渠道会自己处理过长的文字。

## 怎么出

1. 先把要写的内容和依据备齐：文件读完，要搜的搜完，每个事实性说法都有出处。报告里的每条引用后面会被逐条核对。
2. 在一次 `run_python` 里用组件库拼好并保存。`run_python` 的变量不保留，要分几次写就用 `report.save_json("x.json")` 存、`Report.load_json("x.json")` 读回来接着写。生成 PDF 前一定先 `save_json`，交付被拒时要靠它改。
3. 用 `write_file` 保存生成的文件，得到 file_id，再用 `deliver_file` 交付。交付前引用不通过会被拒绝，提示里每条前面的方括号编号是引用在报告里的序号，后面写了摘抄从哪里开始对不上、原文接着是什么。不要重写整份脚本：`r = Report.load_json("x.json")`，对每条调用 `r.requote(编号, 新摘抄)`，再 `r.save_json`、`r.save_pdf`，重新 `write_file` 和交付。
4. 回答里用文字说明这是什么文件、结论是什么。文件在你这一轮回答结束时才发出，不要写成"已发出"。

## 组件库

```python
import sys
sys.path.insert(0, "skills/report")
from eva_report import Report

r = Report("宁德时代 2024 年度财务核查报告")
r.cover("基于年报与公开网页的交叉核对", [("数据截止", "2025-03-31"), ("文件", "年报.pdf")])  # 封面必须第一个，可省略
r.heading("结论摘要")                      # 一级标题，自动编号 01、02…
r.paragraph("营业收入 **3,620 亿元**【年报.pdf#b12「营业收入 3,620 亿元」】，详见[官网](https://www.catl.com)。")
r.callout("网页内容未经核实，数字请与年报原文核对。", "warn")   # info / ok / warn / bad
r.heading("分项数据")
r.heading("收入与利润", 2)                 # 二、三级标题不编号
r.table(["指标", "2023", "2024", "来源"], [["营业收入", "4,009", "3,620", "【年报.pdf#b12「营业收入 3,620 亿元」】"]],
        caption="表 1 主要指标", col_widths=[3, 1.5, 1.5, 4])
r.figure("chart.png", "图 1 近三年营业收入", width_pct=80)   # png、jpg；svg 只能出 PDF 和 md
r.bullets(["要点一", "要点二"])             # ordered=True 是编号列表
r.web_source("w1", "网页标题", "https://example.com/1", site="某财经网", date="2025-03-30")  # 正文引用了 w1 就必须登记
r.save_pdf("报告.pdf")                     # 或 r.save_docx("报告.docx")、r.save_markdown("报告.md")
```

- 文字里可以写：`**粗体**`、`[文字](https://…)`、换行 `\n`，以及下面的引用。段落、列表项、表格单元格、图题、提示框里都能用。
- 数字请先格式化成字符串再放进表格，`None` 不接受。
- 输出的版式、字体、配色由 `skills/report/theme.yaml` 决定，不要在代码里另设。
- 本机缺系统库导致 PDF 出不来时会报错，说明是环境问题。改出 docx 交付，并在回答里明确告诉用户 PDF 没生成的原因和已改为 Word，不要悄悄换格式。
- 保存时会检查内容；中文字体缺失、引用格式不对、网页引用没登记来源都会直接报错，按提示改。

## 引用和链接

- 文件引用写成 `【文件名#b块号「摘抄原文」】`，纯文本文件用行号 `【文件名#L起始行-结束行「摘抄原文」】`。摘抄必须逐字取自 `read_file` 返回的原文。
- 网页引用写成 `【w编号「摘抄原文」】`，编号取自 `web_search`，摘抄逐字取自该条的标题或正文。用到的每个网页编号都要 `web_source` 登记，标题、站点、日期、链接照搬 `web_search` 的结果，链接不能自己写。
- 企业数据引用写成 `【q编号「摘抄原文」】`，编号取自 `query_company` 返回的 `[q编号]`，摘抄逐字取自该条记录。不需要登记来源，来源里显示「企业数据（企查查）」和摘抄，用户看不到编号。
- **摘抄只取支撑这个事实的一个字段**，如「持股比例：13.54%」，不要把几个字段拼在一起，也不要跳过中间的字段（例如跳过「成立日期」把前后连起来）：摘抄必须是原文里连续的一段，拼接的最容易被拒。企业数据里「当事人」这类字段是带引号的结构（`{"原告": [...]}`），摘抄几乎一定对不上，不要摘它；案件摘「案号」「案由」就够。
- 交付被拒时按提示改摘抄，**不要删掉那条引用**：场景报告交付前还会核对每个维度有没有被引用，删了会因为维度没覆盖再被拒一次。
- 场景 skill 要求声明场景时（如尽调），调用 `r.scenario("场景名", 信用代码, gaps={维度名: 没查的原因})`。交付前会按场景核对必备维度有没有覆盖，具体规则看那个场景的 skill。
- 渲染时每条引用变成正文里的编号角标 `[1]`，点击跳到文末"来源"，来源里有"回到正文"。相同的引用共用一个号。网页来源带可点击的链接。
- 不确定的说法没有依据就不要写，不要为了版面好看补一条引用。网页内容与用户文件不一致时以文件为准，在报告里写明两边各是什么。

## 版面建议

- 结论放最前面，一页内让人看懂要点；数据放表格，趋势放图；一级标题不超过七八个。
- 提示框用来放风险、前提和待核对事项，不要整页都是提示框。
- 图用 matplotlib 画并存 png。中文要设字体：`plt.rcParams["font.sans-serif"] = ["WenQuanYi Micro Hei", "Noto Sans CJK SC", "Microsoft YaHei"]`，`plt.rcParams["axes.unicode_minus"] = False`。用主题里的深蓝 `#1f3a5f` 做主色，别在图里另配一套颜色。
- 页码、页眉页脚、封面样式不用管，组件库统一处理。
