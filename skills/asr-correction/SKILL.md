# 转写纠错

语音识别的错字集中在同音近音字、公司名、行业术语上。纠错的做法是：你读稿、给出一份**改动清单**，脚本逐条检查并应用，你不重写整篇稿子。

## 先分清要做哪件事

- **纠错**（默认）：只改听错的字和乱句，不动意思。可提的改动：错别字、漏字、乱句（`kind=fix`，一条改多长都行，但要用原话里有的字，不补写）；重复、乱码（`kind=tidy`，只删字）；数字念重（`kind=number_fix`）；说话人切错了（拆块 `split`、合并 `merge`、改说话人 `relabel`，见下）。口语改书面语、补全、换说法不是纠错，不要提。
- **口语整理成稿**：用户明确说"整理成稿""去口语""润色成书面"才做。删去语气词、口吃重复、无关闲聊，同时仍要纠错。只删字，不理顺句子、不改说法、不换成书面词、不添内容。
- 用户只要看录音说了什么、没提纠错的，不要主动改，原样给转写。

## 步骤

1. 用 `read_file` 读完整份转写（每页都读），了解谁在说什么、谈的是哪家公司哪个行业。用户在对话里给的背景（公司、人名、术语）也是线索。
2. 挑出读起来别扭、疑似听错的词，把它们（可带前后一两个字）交给 `search_hotwords`，看有没有读音相近的公司名和术语。`match` 为 `exact` 的说明写法已经对了，不要改；`known_mishearing` 是用户以前确认过这个错写就是它，可以直接改。`source` 为 `tenant` 的是本租户用户确认过的，比公共表更可信。候选只是线索：上下文说的明明是别的东西就不要改。
3. 用 `export_transcript` 得到转写稿的 file_id，在 `run_python` 里（`file_ids` 带上它）写改动清单并交给闸门：

```python
import sys
sys.path.insert(0, "skills/asr-correction")
from eva_asr import load_transcript, apply_changes, save

transcript = load_transcript("inputs/<file_id>/访谈_转写稿.json")   # 路径见 run_python 返回的 inputs
changes = [
    {"block": 3, "old": "宁得时代", "new": "宁德时代", "reason": "热词表：公司名", "kind": "fix"},
    {"block": 5, "old": "嗯，那个，就是", "new": "", "reason": "口语废话", "kind": "tidy"},   # 只有用户要求整理成稿时才用 tidy
]
result = apply_changes(transcript, changes)
print(len(result["applied"]), "处已应用")
for r in result["rejected"]:
    print("未应用：", r["change"], r["reason"])
print(save(result, "访谈"))   # 写出 访谈_校正稿.md、访谈_修改清单.md、访谈_校正稿.json
```

4. 看 `rejected`：每条都有原因。能按原因改好的（比如 `old` 不唯一就带上前后文）改了重新提交；闸门挡下的数字类改动和读音差太远的改动**不要换个写法硬塞**，写进给用户的说明里让用户确认。
5. 用 `write_file` 保存校正稿和修改清单，`deliver_file` 交付给用户。回答里说明：改了多少处、主要改了哪些名字、哪些没改或没把握、数字类的存疑处。
6. 没把握的名字，问用户"访谈里的 X 是不是 Y"。用户明确答复后，用 `confirm_term` 记下正确写法（term）和常被听成的错写（heard_as），下次纠错就能直接用；用户说记错了，用 `remove` 删掉。

## 说话人切错了：拆块、合并、改说话人

录音转写按说话人切块，切错有三种。

- **挤在一起**（问和答在同一块，几段都可能）：`{"block": 8, "kind": "split", "parts": [["S1", "有其他的资产受限吗？"], ["S2", "没有，没有。"]], "reason": "…"}`。`parts` 是按说话顺序排的几段 `[说话人标签, 这一段原文]`，标签必须是转写里已有的，各段拼起来必须正好是这个块的原文（不增减改字，改字放到拆块之后）。第一段留在原块，后面各段成为紧跟在它后面的新块（块号依次往后排），沿用原块的时间。
- **一个人的话被切开**：`{"kind": "merge", "blocks": [13, 14], "reason": "…"}`。块必须相邻、按顺序写、说话人相同；合并后沿用第一个块号，时间从第一块的开头到最后一块的结尾。
- **整块归错人**：`{"kind": "relabel", "block": 6, "speaker": "S2"}`。

这三种放在清单最前面，合并在先，之后要改字，用合并后或拆块后新块的块号。拆不拆、合不合由你判断，闸门只查机械条件：块和标签存在、相邻、不丢字。
## 规则

- `old` 必须逐字取自该块当前文本，且在块内只出现一次（`tidy` 可加 `"all": True` 删掉块内每一处）；不要改块首的说话人标签（如 `S1：`）。
- `tidy` 只能删字：改后必须是改前删去若干字的结果，不换词。`old` 取要删的那一小段，不要把整句抄进去。
- 不自己改数字、金额、日期、百分比。转写里的数字错了改错的代价大，被闸门挡下的列给用户确认。唯一的例外是 `kind="number_fix"`：语音识别把数字念重了（`202025年9月`→`2025年9月`、`700700万`→`700万`），或改后的数字在全文别处原样出现过，闸门才放行，并记下依据。
- 被拦下的改动，返回里有 `applicable`：`True` 表示用户确认后可以应用（数字、长度、读音等规则拦的），`False` 表示位置或格式不对，应用不了。
- 不确定就不改，列出来。宁可漏改，不要把对的改错。
- 说话人编号是录音转写给的，不要自己合并或改名。
- `confirm_term` 只在用户明确答复了你的确认问题之后调用。你自己推断的、用户没回答过的，不要记。
- **引用只认原始转写**：报告或回答里引用录音内容时，摘抄必须取自 `read_file` 返回的原始转写块。校正稿不能当引用来源，需要时在文字里说明"原始转写为…，校正为…"。
